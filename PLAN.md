# PLAN.md — Реверс-инжиниринг оригинальной M.A.X. и Rust-клиент под Horizon

Версия: 3.0 · 2026-11-13
Предыдущие версии плана (P2P-арбитр v1, клиент-сервер на C++ v2) — закрыты: клиент теперь
пишется заново на Rust, C++-headless остаётся сервером-авторитетом.

## 1. Решение

1. **Источник истины для игровой логики — оригинальная игра** в
   `D:\dev\max-port-debug\max-original` (MAXRUN.EXE, DOS/4GW) + кодовая база
   C++-порта M.A.X. Port (уже содержит оригинальные имена функций, структур и констант —
   используем её как розеттский камень для сопоставления).
2. **Реверс-инжиниринг** — систематический: дизассемблирование MAXRUN.EXE, каталог функций
   (адрес → имя → назначение → связи), структуры данных, форматы файлов, сетевой протокол
   оригинала. Всё документируется в `max-original/RE/`.
3. **Клиент пишется на Rust** в `D:\dev\max-port-debug\client-rust-port` — **не порт 1:1**,
   а осмысленная модульная архитектура, изначально заточенная под клиент-сервер с Horizon
   (ввод на сервер, авторитетное состояние обратно — протокол из PLAN v2, раздел 4).
4. C++-headless-сервер (max-port --server под Horizon) остаётся игровым авторитетом;
   C++-клиент и его P2P-меш больше не развиваются.

## 2. Фазы

### Фаза RE1 — Инструменты и первичный разбор MAXRUN.EXE
- Идентификация формата (MZ + LE/LX, DOS/4GW), карта сегментов, точка входа.
- Инструменты в Docker: radare2 (быстрые листинги) + Ghidra headless (декомпиляция,
  экспорт БД). Скрипты экспорта: функции, xrefs, строки, импорты DOS4GW.
- **Критерий**: `max-original/RE/01-overview.md` — формат, entry, сегменты, строки и
  первые N функций с адресами; экспорт-скрипты в `max-original/RE/tools/`.

### Фаза RE2 — Сопоставление с C++-портом (розеттский камень)
- Извлечение строк из MAXRUN.EXE → сопоставление со строками исходников C++
  (`GameManager_*`, `AiPlayer_*`, `UnitsManager_*`, меню, тексты).
- Каталог функций: таблица `addr → C++-имя → файл/модуль → назначение` (CSV/MD).
- Структуры: UnitInfo, TeamInfo, миссии, ресурсы — сверка раскладок с заголовками C++.
- **Критерий**: каталог покрывает ≥80% функций C++-ядра, `max-original/RE/functions.csv`
  + `structures.md`.

### Фаза RE3 — Форматы данных и протоколы
- Форматы: RES/PATCHES, карты (WRL/SCE/MPS), спрайты SPW, анимации FLC, FON, MSC/MVE.
- Сетевой протокол оригинала (пакеты, хендшейк, lockstep) — документирование как
  историческая справка; в новом клиенте используется протокол Horizon-клиента.
- **Критерий**: `max-original/RE/formats/` — по одному документу на формат с полями и
  примерами байтов.

### Фаза R1 — Каркас Rust-клиента (модульная архитектура)
- Workspace в `client-rust-port`: `core` (игровое состояние, юниты, команды — чистый,
  без I/O), `net` (wire-протокол клиент↔Horizon: WS + UDP к headless, тикеты), `render`
  (SDL3/пиксели, UI), `assets` (загрузка RES/PATCHES/SPW/FLC), `app` (клеевой слой).
- Строгие границы: core не знает про сеть; net не знает про рендер; состояние — через
  события/снапшоты сервера.
- **Критерий**: workspace собирается, тесты core/net зелёные, каркасные типы протокола
  (join/state/orders) определены.

### Фаза R2 — Игровой цикл клиента и подключение к Horizon
- Запрос лобби (WS), тикет, UDP-подключение к headless, хендшейк, получение настроек и
  снапшота состояния, отображение мира и юнитов.
- **Критерий**: Rust-клиент видит список игр Horizon, входит в сессию и рендерит мир
  и юнитов с серверного состояния.

### Фаза R3 — Играбельность
- Ввод: приказы юнитам → сервер, подтверждения, конец хода, чат; интерполяция и
  предпросмотр приказов.
- **Критерий**: два Rust-клиента играют партию против headless-сервера 10+ ходов
  без расхождений.

### Фаза R4 — Доводка и эксплуатация
- Реконнект (SNAP), спектатор, звук/видео-ролики, CI сборки, документация.

## 3. Инструментарий и модели (конвенция делегирования)

- **Сложные рассуждения и анализ** (RE-разбор, архитектурные решения, дизайн протокола) →
  субагенты на **DeepSeek-V4-Pro, Effort Max**: `provider: deepseek-account`,
  `model: deepseek-v4-pro` (Effort Max задаётся профильной настройкой
  `agent-default-model.reasoningEffort: max`).
- **Генерация кода и скриптов** (Rust-крейты, Python/PowerShell-скрипты, Ghidra-скрипты,
  драйверы) → субагенты на **DeepSeek-V4.1-Flash**: `provider: deepseek-account`,
  `model: deepseek-flash`.
- Политика выбора моделей субагентов включена в профиле (`subagent-model-selection-settings`,
  маршруты `deepseek-account/deepseek-v4-pro` и `deepseek-account/deepseek-flash`);
  проверено в workflow-пробе: оба маршрута возвращают OK.
- Оркестрация — workflow-инструмент Harness с `phase`/`provider`/`model` на агента;
  результат каждого агента валидируется в основном потоке.
