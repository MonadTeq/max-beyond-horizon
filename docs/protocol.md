# Протокол клиент ↔ Horizon (черновик спецификации)

> Статус: СКЕЛЕТ. Заполняется по мере извлечения контракта из сетевого слоя
> C++-порта (`src/transport_*.cpp`, коды сессий в `max-horizon-server`).
> Этот протокол заменяет P2P/lockstep оригинала; оригинальный протокол
> документируется отдельно в `max-original-dasm/formats/original-net.md`
> как историческая справка.

## 1. Топология

```
Rust-клиент ──WS (лобби/админ)──► Horizon (max-horizon-server)
Rust-клиент ──UDP (игровая сессия)──► headless max-port (авторитет)
```

## 2. Фазы соединения

1. **Лобби**: WS-запрос списка игр; создание/вход в сессию → тикет.
2. **Подключение**: UDP к headless-адресу из тикета; хендшейк (версия, id сессии,
   тикет) → принятие.
3. **Игра**: сервер шлёт снапшоты состояния; клиент шлёт команды/ввод.
4. **Реконнект**: SNAP-запрос полного состояния при разрыве.

> Заполнить: точные имена, кодирование, порядок полей, тайминги — из кода

## 4. Инварианты

- Сервер — единственный авторитет; клиентские предпросмотры не меняют состояние.
- Порядок команд от клиента сериализуется сервером; подтверждение — только из
  снапшота/дельты.
- При расхождении клиент обязан перезапросить снапшот (SNAP).
