# Barrier Flow: 00 / 45 / 52 (и 01 / 53 / 54 / 06 / 51) в топологии «звезда»

> Статус: ЗАПОЛНЕНО из кода `src/remote.cpp`, `src/transport_udp_default.cpp`,
> `src/game_manager.cpp`, канона `max-cpp-port/src/remote.cpp` и Rust-стороны
> (`max-rust/crates/max_net/src/session.rs`, `max-rust/crates/max_app/src/net.rs`,
> `max-rust/crates/max_core/src/{events,game,crc}.rs`). Сопутствующие раскладки —
> `docs/protocol.md` §7–8.
>
> Диагноз живого smoke (§7) и список исправлений (§8) описывают, почему партия
> двух Rust-клиентов через headless-сервер сейчас не стартует и что должно
> измениться, чтобы барьеры завершались.

## 1. Роли в звезде

```
Rust client A ──┐                                   ┌── Rust client B
 (команда RED)   │  ENet APPL (канал 1)              │   (команда GREEN)
                 ▼                                   ▼
           headless max-port (C++ fork src/)
           · полная детерминированная симуляция, своей команды НЕТ
           · арбитр барьеров: ждёт согласия всех команд (Remote_ServerWaitBarrier)
           · реле: должен пересылать APPL-пакеты клиента A клиенту B и наоборот
```

- Клиент в звезде соединён **только** с сервером. В транспорте клиента любой
  исходящий APPL-пакет превращается в broadcast на его единственного пира —
  сервер: `src/transport_udp_default.cpp:867-872` (`local.ClearAddressTable()`).
- Сервер шлёт свои пакеты (13 seed, 17 настройки, 32/34/44/47/30/51) клиентам
  напрямую: `Remote_TransmitPacket(..., REMOTE_MULTICAST)` адресует их всем
  нодам `Remote_Nodes` (`src/remote.cpp:993-1013`).
- Пакеты клиента A, адресованные «всем», доезжают **только до сервера**;
  дальше их должен **релеить сервер** — этого кода в текущей развилке НЕТ
  (см. §7): комментарий «the server relays it to the other clients»
  (`transport_udp_default.cpp:867-869`) не подкреплён реализацией.
- Адресация по содержанию: `Remote_GetSenderTeam()` определяет отправителя по
  адресу источника (`remote.cpp:1237-1249`), но **барьерные обработчики 00/01/45/52
  источник не проверяют вовсе** — команда читается из поля `team u16` внутри
  пакета. Поэтому реле сервера корректно для барьеров даже при том, что на
  приёме «отправителем» будет значиться сервер (у него нет команды → -1).

## 2. Сводка пакетов и их семантика

| Пакет | Кто шлёт | Кто принимает | Поля | Смысл |
|---|---|---|---|---|
| **00** | клиент | все (реле) | `team u16, counter u8` | барьер **начала хода**: «я вошёл в раунд counter» |
| **01** | клиент | все (реле) | `team u16, counter u8 (6 бит)` | покадровый sync (real-time pacing) |
| **06** | клиент | все (реле) | `team u16` | «команда завершила ход» (`finished_turn = 1`, в пошаговом — `GameState = END_TURN`) |
| **52** | клиент | все (реле) | `team u16, counter u8` | барьер **конца хода**: «я дошёл до барьера раунда counter» |
| **53** | владелец команды | все (реле) | `team u16, turn i32, count u16, count×{complex_id u16, 6×i16}` | итоги баз на начало хода (экономика) |
| **54** | владелец команды | все (реле) | `team u16, sync_index u8, is_last bool, count u16, …` | авторитетное состояние юнитов команды (аналог снапшота) |
| **45** | клиент | все (реле) | `team u16, next_turn_index u8, crc16 u16` | барьер **CRC**: «мой CRC мира после хода = crc16» |
| **51** | **сервер** | все клиенты | `team u16, param u8` | «десинк» → клиенты пишут desync-отчёт / рестарт с автосейва |

**Ни один барьер не имеет «ответа» в смысле ack:** барьер считается
пройденным, когда пир получил значение счётчика **от каждой удалённой
команды**, равное его собственному. Сервер-арбитр ничего не эхо-шлёт и сам
барьерных пакетов не генерирует (у него нет команды) — он только наблюдает и
сравнивает (`Remote_ServerWaitBarrier`).

### 2.1 Кто и когда (клиентская сторона, из `src/remote.cpp`)

- **00** — `Remote_WaitBeginTurnAcknowledge()` (`remote.cpp:1876-1933`):
  `++Remote_FrameSyncCounter[своя команда]` → отправить 00 → ждать, пока у
  **всех** удалённых команд `Remote_FrameSyncCounter[team] == своё значение`;
  повтор каждые 3 с (`REMOTE_PING_TIME_PERIOD`, строка 63), таймаут 30 с
  (`REMOTE_RESPONSE_TIMEOUT`, строка 61) на отстающую команду →
  `Remote_ResponseTimeout(team, true)` (элиминация). Вызовы: загрузка партии
  (`game_manager.cpp:3560`), начало каждого хода в одновременном режиме
  (`game_manager.cpp:496`, `GameManager_TeamTurnConcurrent`).
- **01** — `Remote_Synchronize()` (`remote.cpp:1794-1874`): клиент раз в ~2 мс
  шлёт 01 со счётчиком `Remote_FrameSyncCounter2` (6 бит) и ждёт, пока у каждой
  удалённой команды `FrameSyncCounter2values[team] == (свой − 1) & 0x3F`.
  Сервер-арбитр 01 не шлёт и кадровых позиций пиров не ждёт
  (`remote.cpp:1804-1815`).
- **06** — `GameManager_EndTurn`-путь: `game_manager.cpp:898-900`
  (`Remote_SendNetPacket_Signal(REMOTE_PACKET_06, team, 0)`), когда команда
  нажала «конец хода» (пошаговый режим переводит всех в `GAME_STATE_9_END_TURN`).
- **52** — `Remote_WaitEndTurnAcknowledge()` (`remote.cpp:1935-1991`): та же
  схема, что 00, но со счётчиком `Remote_TurnIndices[team]`; вызывается из
  `Access_AreTaskEventsPending` (`access.cpp:2312-2314`), когда весь локальный
  ввод/движение этого хода обработаны.
- **53** — владелец шлёт свои итоги баз в начале экономики
  (`GameManager_ManageEconomy`, `game_manager.cpp:2083-2089`); каждый пир ждёт
  53 **каждой удалённой команды** за текущий `GameManager_TurnCounter`
  (`Remote_WaitComplexTotals`, `remote.cpp:4286-4331`).
- **54** — `Remote_SynchronizeUnitStates()` (`remote.cpp:4654-4708`):
  `++Remote_StateSyncIndex` → владелец шлёт состояние **своей** команды
  (`Remote_SendUnitStates`, `remote.cpp:4333-4381`) → ждать, пока у всех
  удалённых команд `StateSyncIndices[team] == своё значение`.
- **45** — `Remote_CheckDesync(team, crc)` (`remote.cpp:2207-2300`): после 54
  считается CRC мира (`GameManager_CheckDesync`, `game_manager.cpp:2442-2492`,
  начальное `0xFFFF`, списки GroundCover→MobileLandSea→Stationary→MobileAir,
  команды RED..ALIEN) → `++Remote_NextTurnIndices[team]` → отправить 45 →
  ждать, пока у всех удалённых команд `NextTurnIndices == своё` → сравнить
  `Remote_TeamDataCrc16[team] == свой CRC`. Расхождение → сервер шлёт 51.

Порядок за ход (пошаговый и одновременный отличаются лишь местом 00-барьера):

```
[загрузка: 00(1)] → [00 каждый ход — только SimultaneousMoves]
→ 53 (экономика) → тики/приказы (08/38/41/50…) → 06
→ 52 → 54 → 45 → следующий ход
```

### 2.2 Сервер-арбитр (`Remote_ServerWaitBarrier`, `remote.cpp:607-670`)

- Барьер завершён, когда `min == max` по всем удалённым командам **и**
  `max > *last_value || *last_value != 0`; после завершения `*last_value = max`.
- Счётчики на проводе обязаны быть **≥ 1 в первом раунде** (C++ клиент всегда
  шлёт `++counter` от нуля → 1): условие `max > last` при `last == 0` не может
  отличить «пиры согласились на 0» от «данные ещё не пришли» — при нулевых
  счётчиках арбитр висит вечно.
- Арбитр сам никого не элиминирует: при расхождении логирует отстающую команду
  раз в 30 с и продолжает ждать (`remote.cpp:643-656`).
- Серверные ветки барьеров: 00 — `remote.cpp:1877-1881`, 52 — `1936-1940`,
  45 — `2208-2231`, 54 — `4655-4660` (после 45-согласия сервер сравнивает
  `Remote_TeamDataCrc16[i]` со своей симуляцией и шлёт 51 при расхождении).

## 3. Точный конечный автомат барьеров КЛИЕНТА

Обозначения: `R` — множество удалённых команд (`TEAM_TYPE_REMOTE`),
`own` — своя команда. Повтор и таймаут едины для всех барьеров:
**повтор каждые 3 с, таймаут 30 с** (после таймаута C++ элиминирует
отстающую команду; Rust — логирует и ждёт, арбитр сам не исключает).

```
СОСТОЯНИЕ BEGIN (00):
  counter = prev + 1                 # C++: ++Remote_FrameSyncCounter[own]; первый раунд = 1
  отправить 00(own, counter)
  while ∃ team ∈ R: FrameSyncCounter[team] != counter:
      pump пакетов; слать 01 (кадровый); повтор 00 через 3 с; таймаут 30 с
  → PLAY

СОСТОЯНИЕ PLAY (экономика + ввод):
  отправить 53(own, turn=GameManager_TurnCounter, комплексы)
  while ∃ team ∈ R: не получен 53(team) за текущий turn:
      pump; повтор 53 через 3 с; таймаут 30 с        # Remote_WaitComplexTotals
  применять 08/38/41/50/11/… по мере прихода; слать 01 каждый кадр
  локальный ввод обработан → отправить 06(own)
  когда локальная очередь хода пуста → END

СОСТОЯНИЕ END (52):
  counter = prev + 1                 # C++: ++Remote_TurnIndices[own]; первый раунд = 1
  отправить 52(own, counter)
  while ∃ team ∈ R: TurnIndices[team] != counter:
      pump (применять приходящие 08/06/52); слать 01; повтор 52 через 3 с; таймаут 30 с
  → SYNC

СОСТОЯНИЕ SYNC (54):
  index = prev + 1                   # ++Remote_StateSyncIndex
  отправить 54(own, index, юниты своей команды, [tail если last])
  while ∃ team ∈ R: StateSyncIndices[team] != index:
      pump; применять входящие 54; повтор 54 через 3 с; таймаут 30 с
  → CRC

СОСТОЯНИЕ CRC (45):
  crc = CRC16(0xFFFF, списки юнитов)  # max_core::crc::state_checksum
  index = prev + 1                   # ++Remote_NextTurnIndices[own]; первый раунд = 1
  отправить 45(own, index, crc)
  while ∃ team ∈ R: NextTurnIndices[team] != index:
      pump; повтор 45 через 3 с; таймаут 30 с
  if ∃ team ∈ R: TeamDataCrc16[team] != crc:
      # десинк: сервер пришлёт 51; писать отчёт, рестарт с автосейва
  → finish_turn() → BEGIN
```

Связь с `GameState`/концом хода: 06 ставит `finished_turn = true`
(`remote.cpp:2359-2398`, в пошаговом — `GAME_STATE_9_END_TURN`); 52 закрывает
барьер, после чего все пиры одновременно выполняют `GameManager_TeamTurnFinish`
(сброс `finished_turn`, `++GameManager_TurnCounter`, проверка победы,
`game_manager.cpp:583-630`); 45/54 идут ДО перехода на следующий ход и
удостоверяют, что миры совпали.

## 4. Диаграмма обмена (звезда, 2 клиента)

```
A (RED)                headless (арбитр+реле)             B (GREEN)
   │  00(0x50, RED, c=1) ────────►│                              │
   │                              ├─── 00(RED, c=1) ───────────► │   (реле)
   │ ◄────────────────── 00(GREEN, c=1) ─────────────────────────┤
   │  00-барьер пройден: FrameSyncCounter обоих == 1             │
   │  53(RED, turn, …) ──────────►│                              │
   │                              ├─── 53(RED, …) ─────────────► │
   │ ◄────────────────── 53(GREEN, …) ───────────────────────────┤
   │  01, 01, … (кадровые, каждые ~2 мс)  ◄═ реле ═►             │
   │  06(RED) ───────────────────►│                              │
   │                              ├─── 06(RED) ────────────────► │
   │  52(0x84, RED, c=1) ────────►│                              │
   │                              ├─── 52(RED, c=1) ───────────► │
   │ ◄────────────────── 52(GREEN, c=1) ─────────────────────────┤
   │  52-барьер пройден: TurnIndices обоих == 1                  │
   │  54(0x86, RED, i=1, units) ─►│                              │
   │                              ├─── 54(RED, i=1, …) ────────► │
   │ ◄────────────────── 54(GREEN, i=1, …) ──────────────────────┤
   │  45(0x7D, RED, i=1, crc) ───►│                              │
   │                              ├─── 45(RED, i=1, crc) ──────► │
   │ ◄────────────────── 45(GREEN, i=1, crc) ────────────────────┤
   │  арбитр: crc_RED == crc_GREEN == серверная симуляция?        │
   │        если нет → 51(0x83, team, 0) всем клиентам           │
   │  клиенты: свои CRC совпали со всеми R → finish_turn         │
   └────────────────────── следующий ход ────────────────────────┘
```

Без реле правая половина стрелок отсутствует: A никогда не видит 00/53/52/54/45
команды GREEN → его барьеры висят до 30-секундного таймаута.

## 7. Диагноз живого smoke

1. **Реле отсутствует.** `TransportUdpDefault_ProcessApplPacket`
   (`transport_udp_default.cpp:778-817`) на сервере только кладёт пакет в
   `RxPackets`; пересылки другим клиентам нет. Клиент A не видит ни одного
   пакета клиента B (и наоборот) → все клиентские барьеры
   (00/52/45 и ожидания 53/54) висят до таймаута.
2. **Арбитр застревает на первом же 00.** Оба Rust-клиента шлют 00 с
   `counter = 0`; `Remote_ServerWaitBarrier`: `min == max == 0`, `last == 0` →
   условие `(0 > 0 || 0 != 0)` ложно → `done = false` навсегда (сервер
   логирует «team N is lagging» раз в 30 с, но не выходит). «Main game loop
   start.» — последнее, что печатает сервер.
3. Даже после фиксов 1–2 сервер встанет на **53** (Rust не шлёт), затем на
   **54**, затем на **45** — цепочка в §6.
4. Клиентская сторона: `BarrierTimeout` по 00/52 (трекер сессии + трекер
   max_app), пакет 45 не шлётся вовсе, 54 входящие не применяются.

   ```cpp
   if (context->NetRole == TRANSPORT_SERVER) {
       NetPacket relay;
       relay.Write(enet_packet->data, enet_packet->dataLength);
       for (uint32_t i = 0; i < context->Peers.GetCount(); ++i) {
           ENetPeer* const other = *context->Peers[i];
           if (other == peer || !TransportUdpDefault_IsPeerVerified(other)) continue;
           NetAddress target;
           target.host = other->address.host;
           target.port = other->address.port;
           relay.AddAddress(target);
       }
       if (relay.GetAddressCount() > 0) {
           TransportUdpDefault_LockQueue(context);
           context->TxPackets.push_back(std::move(relay)); /* с лимитом очереди */
           TransportUdpDefault_UnlockQueue(context);
   ```
