# Единый план проекта — M.A.X. : Beyond Rust Horizon

Единственный источник истины по **целям**, **статусу** и **дорожной карте**.
Детализация — по ссылкам на профильные документы; этот файл — общая картина и
разделение ответственности по агентам (см. [`AGENTS.md`](AGENTS.md)).

> Новые задачи фиксируются только в этом документе; детальные рабочие планы —
> по ссылкам в §6.

## 1. Состояние проекта

**Пре-альфа.** Режимы и механики реализованы в коде и покрыты тестами
(1217+ тестов, golden-гейт, CRC-барьеры бит-в-бит с оракулами), но по ручному
тестированию игра ещё сырая и далека от альфы. Закрытие целей — только после
явного подтверждения владельца (правило 4, `qa/README.md`).

## 2. Цели

1. **Играбельный Rust-клиент** с полной детерминированной симуляцией 1:1
   (одиночная игра, hot-seat, сетевая).
2. **Сетевая игра**: выделенный сервер (Horizon + headless-арбитр) — работает;
   режим хоста (P2P) из оригинала — не реализован (**отдельная задача** после
   фасада GameUniverse: миграция хоста по `sequence number`, кворум, split-brain).
3. **Абсолютное сохранение визуала и механик оригинала** + исправление
   известных ошибок оригинала (осознанные расхождения — отдельно).

## 3. Дорожная карта (по приоритету)

### 1. Клиент M.A.X. : Beyond Rust Horizon

#### 1.1 Приведение игровых механик к оригиналу и исправление ошибок (движок)

- **Цель.** Механики `max_core` 1:1 с Оракулом Interplay; известные ошибки
  Interplay исправляются отдельно (цель 3.1); «отсебятина» Оракула Klei не
  переносится.
- **Статус.** В работе: основные механики портированы (производство, экономика,
  комплексы/коннекторы, бой, исследования, мобилизация, сейвы V70), но ручное
  тестирование выявляет дефекты.
- **Задачи.**
  - Дистилляция DSL: приказы/состояния/ресурсы — готово (внесено в `domain-map.md`);
    «Команды и кланы» и «Прочее» (`PlayMode`/`VictoryType`/`GameStateType`/
    `Surface`/`unit_flags`) — в работе.
  - RE-верификация спорных мест (приоритет Interplay) — по мере находок.
  - Исправление дефектов из ручного прогона (см. 1.2/1.3).
  - Цель 3.1: отдельный список известных ошибок Interplay и задачи на них.
- **Ответственные.** Аналитик (DSL/домен), Реверс-инженер (RE), Разработчик
  (код), QA (дефекты).

#### 1.2 Одиночная игра человек против ИИ (1–3 ИИ)

- **Цель.** Полная партия против 1–3 ИИ от меню до экрана победы/поражения без
  дефектов.
- **Статус.** Реализовано (режим M-SP); отладка.
- **Задачи.**
  - Ручной прогон партий (разные планеты, сложности ИИ, условия победы) — сбор
    дефектов.
  - Исправление найденных дефектов.
- **Критерий.** Партия против ИИ проходится полностью без паник/зависаний;
  владелец подтверждает.

##### 1.2.1 Отладка игрового ИИ

- **Статус.** Полный порт ИИ из C++ выполнен (фаза A: вес-таблицы → стратегия →
  производство → бой → исследования → разведка/флот); отладка по ручному прогону.
- **Задачи.**
  - Проверить задачи/стратегии ИИ: строительство, производство, бой, разведка,
    морской флот, апгрейды — портированы; далее — выверка по ручным партиям.
  - Детерминизм ИИ — «та же стратегия, другой seed-путь» (решение владельца);
    бит-в-бит RNG-путь не требуется.
  - Осознанные отклонения порта (TransporterMap, полный `EvaluateAssault`,
    `CopyTargets`/`SupportAttack`) — в `analysis/ai-port-status.md`; при
    необходимости — дозакрыть.
- **Ответственные.** Разработчик, Реверс-инженер (спорные места), QA.

#### 1.3 Hot Seat (человек против человека)

- **Цель.** 2–4 человека по очереди на одном ПК без дефектов.
- **Статус.** Реализовано (режим M-HS); отладка.
- **Задачи.**
  - Отладка переключения команд, окна перехода, таймера хода на каждую команду.
  - Ручной прогон, сбор дефектов.
- **Критерий.** Полная hot-seat партия проходится без дефектов; владелец
  подтверждает.

##### 1.3.1 Hot Seat + игроки ИИ

- **Цель.** Смесь людей и ИИ в одной партии (2–4 команды).
- **Статус.** В работе.
- **Задачи.**
  - Чередование люди ↔ ИИ, блокировка ввода на ходу ИИ, имена команд.
  - Ручной прогон смешанных составов, сбор дефектов.

#### 1.4 Подсистема рендеринга и UI (SDL)

- **Статус.** Основной визуал 1:1 (A1–A9, B1–B5, D1/D3, E1); остатки — ниже.
- **Ответственные.** Разработчик (рендер/UI), Аналитик (сверка с оригиналом),
  QA (golden/ручной прогон).

##### 1.4.2 Отладка рендеринга на современных системах

## 4. Ответственность агентов (сводка)

| Агент | Зона ответственности в дорожной карте |
|---|---|
| **Координатор** | вести план, распределять по компетенциям, эскалировать владельцу |
| **Архитектор** | слои/границы (рефакторинг завершён); консультации по структуре |
| **Аналитик** | DSL/домен (1.1), сверка UI с оригиналом (1.4.1) |
| **Реверс-инженер** | RE-верификация спорных мест по Оракулу Interplay (1.1, 1.2.1) |
| **Разработчик** | движок (1.1), ИИ (1.2.1), режимы (1.2/1.3), рендер/UI (1.4) |
| **QA** | ручной прогон пре-альфа → альфа, golden, дефекты, релизные гейты |

## 5. Порядок эскалации

1. Агент не может решить задачу в своей компетенции → **координатор**.
2. Координатор определяет, какая роль/компетенция нужна для решения вопроса, и
   **делегирует агенту соответствующей роли**.
3. Если роль определить не удалось, или делегат не справился и компетентных
   агентов больше нет → **вопрос владельцу (человеку)**; решение ожидается, не
   домысливается.
