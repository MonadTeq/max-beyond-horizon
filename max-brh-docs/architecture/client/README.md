# Архитектура клиента — план и статус

Цели и текущее состояние клиентской части проекта **M.A.X. : Beyond Rust
Horizon** (`max-brh`). Детализация — по документам каталога.

## Цели

1. **Играбельная версия игры на Rust** с сохранением оригинальных игровых механик.
   1.1. Человек против ИИ (в том числе нескольких ИИ).
   1.2. Человек против человека на одном компьютере (hot-seat) с участием ИИ.
2. **Сетевая игра в режиме хоста** (возможность, имевшаяся в оригинале).
   2.1. Подключение к чужой сетевой игре.
3. **Абсолютное сохранение визуала и игровых механик оригинала.**
   3.1. Исправление известных ошибок оригинала.

## Статус по целям

> **Состояние проекта: пре-альфа.** Режимы и механики реализованы в коде и
> покрыты тестами, но по результатам ручного тестирования игра ещё сырая и
> далека от альфа-версии. Статус «в разработке» означает: функциональность
> присутствует, однако до завершения цели требуются ручные прогоны, устранение
> дефектов и доработки.
>
> **Правило закрытия целей:** статус «выполнено» устанавливается только после
> явного подтверждения человека, что найденные ошибки исправлены и цель можно
> закрыть (см. `../../qa/README.md`). Автоматические прогоны — необходимое, но
> не достаточное условие.

## Текущее состояние сети

Сетевая игра на данный момент реализована через **выделенный сервер**
(Horizon + C++-headless арбитр) — см. `../server/`. Режим **хоста** из
оригинала (один из игроков является хостом, остальные подключаются напрямую
по TCP/IP, Peer-to-Peer) **не перенесён** — цель 2 и 2.1.

Порядок закрытия цели 2 (детальный план — `../../development/PLAN-host-mode.md`):

1. локальный хост-режим: одна из команд клиента принимает роль сервера сессии
   (как `ENet server role` первого пира в оригинале);
2. подключение к чужой игре: клиент-гость вводит адрес хоста и подключается;
3. согласование с существующим lockstep-стеком (`barrier-flow.md`) без участия
   выделенного сервера.
