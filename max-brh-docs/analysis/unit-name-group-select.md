# Имена юнитов и групповой выбор — механики оригинала

Версия 0.1 (Аналитик) · 2026-11-28. Источники: Klei (файл:строка), Interplay (строки-якоря бинарника).

## 1. Порядковый номер экземпляра юнита («Scout 1», «Mk II Scout 7»)

### Две независимые компоненты

| Что | Откуда | Пример |
|---|---|---|
| «Scout 7» — номер экземпляра | счётчик производства на команду и тип (`unit_counters`) | порядок выпуска |
| «Mk II» — марк-уровень апгрейда | `UnitValues::version` (римскими цифрами) | растёт от апгрейдов |

Полное имя: **«Mk II Scout 7»** (кадр оригинала: «Mk I Engineer 1»).

### Хранение (Klei)
- `UnitInfo::name` — пользовательское имя (Option), `unitinfo.hpp:86`.
- `UnitInfo::unit_id: u8` — номер типа в команде, `unitinfo.hpp:414`.
- `UnitInfo::id: u32` — глобальный hash-id (НЕ номер в имени), `unitinfo.hpp:475`.
- `CTInfo::unit_counters[UNIT_END]` — счётчик на команду, старт с 1, цикл 256 (`ctinfo.hpp:103,49-51`; V70 — массив u8, `saveload.cpp:839,852-856`).

### Формирование
- Выдача: `unit->unit_id = unit_counters[type]; ++unit_counters[type]` (`units_manager.cpp:2377-2379`).
- `GetName`: `name` или `"%s %i"` (тип + номер), `unitinfo.cpp:757-779`.
- `GetDisplayName`: `"Mk %s %s"` = римская версия + имя, `unitinfo.cpp:781-803, 805-826, 915-925`.
- Версия по умолчанию 1 → «Mk I».

### Где показывается
угловая панель портрета, полоса описания (hover), заголовок `UnitStats`, список юнитов, оверлей имён, сообщения стройки («Scout 7 will be available in N turns» — счётчик ДО инкремента, `buildmenu.cpp:944-946`).

### Переименование
Клик по имени в угловом окне → `TextEdit` (поле после префикса «Mk I ») → Enter → `SetName` → сетевой пакет 43. Счётчик не трогается.

### Что портировать
данные (unit_id/name/unit_counters, персистентность), форматирование (GetName/GetDisplayName + римские), UI (5 мест), сообщения производства, сетевой пакет переименования.

## 2. Выбор группы рамкой + групповое перемещение

### Рамка
- Якорь при нажатии, порог **16 px** (`game_manager.cpp:4280-4288`), жёлтая рамка (`RenderMultiSelectIndicator`, `:997-1035`), отпускание → `Access_MultiSelect` (`:6513-6525`).
- Клетки: `(ulx+16)/64 … (lrx-16)/64` (`access.cpp:2183-2186`).

### Правила мультивыбора (`Access_MultiSelect`, access.cpp:2177-2253)
- Якорь = выделенный: свой, мобильный, `EXECUTING_ORDER`, в рамке, не disabled.
- Члены: свои мобильные `EXECUTING`/`READY`, не disabled; выдёргиваются из старых групп.
- **Лимит 10** (рамка и Shift+клик); только сам → группа не создаётся.
- `Access_UpdateMultiSelection`: членам `ORDER_AWAIT`, `move_to = attack_site = своя клетка` (снимок строя).

### Групповой приказ (построение сохраняется)
- Приказ только лидеру (`game_manager.cpp:4152-4194`) → `Access_GroupAttackOrder` (`access.cpp:1218-1289`).
- `group_speed = min(speed)+1` (`:1195-1216`) — общий бюджет хода.
- Цель члена = `attack_site − лидер.attack_site + лидер.move_to` (`:1252-1253`), кламп по карте.
- Старт всех после готовности всех путей (`Access_ProcessNewGroupOrder`, `:2321-2368`); неудача пути лидера → группа распускается.
- `ORDER_MOVE_TO_UNIT` (загрузка в транспорт) → группа разбирается.

### Отображение
жёлтые уголки у членов (`drawmap.cpp:674-690`), полный селектор у лидера (`:813-833`), лидер = голова `unit_list`.

## Открытые вопросы владельцу
1. DSL-имена: `unit_counters → team_unit_counters`; группа → `UnitGroup`; `group_speed → бюджет хода группы` (согласование до правки domain-map).
2. **«Scout Mk2»**: в оригинале «Mk» — версия апгрейда, номер экземпляра — арабская цифра («Scout 7»). Если нужен «Mk» как номер экземпляра — отклонение от оригинала, решить.
3. Точные адреса функций оригинала — работа Реверс-инженера по строкам-якорям (0x00171ED1 «%s %i» и др.).
