# MAXRUN.EXE — реальная точка входа и стратегия поимки в DOSBox-X

Восстановлено 2026-11-14 по материалам сессии (оригинал документа потерян при аварии).

## 0. TL;DR

| Вопрос | Ответ |
|---|---|
| Экстендер | **DOS/32A v9.1.2** (build 04-20-06), DOS/4GW-совместимый, bound |
| Вход реального режима (MZ entry) | `CS:IP = (T+0x2DD):0x2C6C` = файл 0x5ABC; **T** — параграф загрузки MZ-образа |
| Первый INT 21h стаба | `AX=0xFF87` в `(T+0x2DD):0x0011` (файл 0x2E61) — приватный зонд DOS/32A |
| Переключение RM→PM (`xr_rmtopmsw`) | `(T+6):0x1141` (файл 0x1221): `lidt cs:[0x3C]; lgdt cs:[0x34]; mov eax,cr0; or al,1; mov cr0,eax; jmp far 0008:115D` |
| Селектор дальнего перехода | **0008** — GDT[1]: 16-битный код, база `T*16+0x60`, лимит 0xFFFF |
| Первая инструкция в PM | линейный `T*16+0x11BD` (файл 0x123D, `pop ds`) |
| Вход ядра в PM (`@@swpm`) | CS=0008, EIP=0xA42 → линейный `T*16+0xAA2` (файл 0xB22) |
| Финальный IRETD в игру (`enter_32bit_code`) | файл 0x5CA7 → линейный `T*16+0x5C27` |
| **Точка входа игры (статически)** | **0x10C704** = база объекта LE #1 (0x10000) + LE.eip (0xFC704); там `EB 76` через баннер «WATCOM C/C++32 Run-Time system» |
| **Точка входа игры (рантайм)** | **0x20D714** = XMS-база загрузки объекта 0x110010 + 0xFC704 |
| Загадка 0x23C704 | Артефакт 0-индексации: LE нумерует объекты с 1 (`eip_object=1` = obj0) |

## 1. Компоновка файла

Bound-компоновка DOS/32A:

```
0x00000..0x0007F  MZ-заголовок: CS:IP=0x02DD:0x2C6C, SS:SP=0x06B1:0x0008, e_lfanew=0x6B90
0x00080..0x006B8F  DOS32A.EXE целиком (стаб + ядро + строки)
    0x00080: "ID32" + конфиг/данные ядра
    0x000E0: база кодового сегмента ядра
    0x01221: xr_rmtopmsw — переключение в PM
    0x05ABC: MZ-entry стаба
    0x05C8E..0x05CA9: финальный запуск приложения (pushfd/iretd)
0x006B90..0x003AAFF  LE-файл приложения (заголовок + таблицы + fixups)
0x003AB00..конец    страницы данных LE (file = 0x3AB00 + (page-1)*0x1000)
```

Объекты LE (таблица по смещению 0x6B90+0xC4, записи по 24 байта):

| # | vsize | base | страниц | первая | назначение |
|---|-------|------|---------|--------|-----------|
| 1 | 0x12D469 | 0x10000 | 302 | 1 | 32-битный код игры |
| 2 | 0x16B | 0x140000 | 1 | 0x12F | ISR последовательного порта COM2 (16-бит) |
| 3 | 0x6F170 | 0x150000 | 36 | 0x130 | данные (строки Watcom и пр.) |

## 2. Рантайм-маппинг (подтверждено динамикой)

- DOS/32A не грузит объекты по предпочтительным базам: `load_object`/`alloc_block`
  выделяют память динамически. Объект #1 (1.18 МБ) не помещается в
  конвенциональную память → берётся XMS-блок из пула ядра.
- В DOSBox-X (memsize=64) первый XMS-блок = **0x110000**, объект #1 получает
  базу **0x110010** (выравнивание +0x10).
- `entry_runtime = base_alloc + LE.eip = 0x110010 + 0xFC704 = 0x20D714`.
- Селекторы приложения: плоские 32-битные 0x1040/0x1048 (CS=1048, база 0x20B000
  на стопе, EIP=0x2714); стек: ESP = base(#3) + 0x6F170.
- T (параграф загрузки стаба) = **0x54C** в этой конфигурации (на первом стопе
  CS=0829 = T+0x2DD).

## 3. Динамическое подтверждение (сделано)

- `BP 20D71:4` (INT3, поставлен в реальном режиме; линейный 0x20D714) сработал
  на входе игры. Регистры на стопе: CS=1048, EIP=0x2714, DS=0058, ES=0068,
  FS=0050, GS=1040, SS=0050, GDT base=0x142D0 limit=0x104F.
- Снять GDT: команда `GDT` (вывод пейджируется — после неё нужен `Q`).

## 4. Команды отладчика (выверено по src/debug/debug.cpp)

- `BP <seg>:<off>` — брейкпоинт исполнения (INT3 пишется в линейный адрес,
  вычисленный при создании: в RM seg*16+off; в PM GetAddress(селектор, off)).
- `BPINT <int> [ah] [al]` — прерывание («*» = любые); в этой сборке работал
  ненадёжно — предпочтение BP.
- `RUN` — продолжить; `RUNWATCH`; `BPLIST`/`BPDEL <n>`.
- `BPM`/`BPPM`/`BPLM` — memory-брейкпоинты (не исполнения).
- `C <seg>:<off>` — код-вью (не continue!); `D` — дата-вью.
- `SR` — ЗАПИСЬ регистров (не чтение!); `SM`/`EV`/`IV`/`SV`/`LV` — память/переменные.
- `GDT`, `SELINFO <sel>`, `PAGING`, `EMU MEM`, `DOS MCBS`/`DOS XMS`/`DOS EMS` — состояние.
- `HELP` — список (пейджируется: ENTER/Q).
- Клавиши UI: F5=Run, F9=bp toggle, F10=step over, F11=trace into.
- Вход в отладчик — DOS-команда `DEBUGBOX` (в autoexec перед запуском игры).

## 5. Соответствие статики и рантайма

`VA_flat` (плоский образ, база 0x10000) ↔ `runtime_linear = base_alloc + (VA_flat - 0x10000)`
для объекта #1. Оффсет внутри объекта одинаков; Ghidra-разметка по плоскому
образу переносится в рантайм сдвигом `base_alloc - 0x10000`.
