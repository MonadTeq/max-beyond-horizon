# MAXRUN.EXE — рантайм-маппинг и почему не срабатывал статический брейкпоинт

Восстановлено 2026-11-14 по резюме Pro-анализа (оригинал потерян).

## Причина неприхода `BP 10C70:4`

Игра исполняется **не по линейному 0x10C704**. DOS/32A не грузит LE-объекты по
предпочтительным базам из таблицы объектов: `load_object`/`alloc_block` выделяют
память динамически. Объект #1 (1.18 МБ) не помещается в конвенциональную память
(AH=48h) → выделяется из пула ядра (int 21h FF91h, заблокированный XMS-блок).
В DOSBox-X первый XMS-блок = 0x110000 (HMA занята DOS), база объекта #1 = 0x110010,
`create_selector` прибавляет её к `_app_eip`.

Механика брейкпоинта в сборке 2022.09 — классический INT3: 0xCC пишется в
`location`, вычисленный один раз при создании BP в реальном режиме; в PM матч
идёт по `GetAddress(CS_игры, EIP)` (CS игры плоский, база 0). 0xCC, записанный
в 0x10C704, ушёл в свободную зону HMA и никогда не исполнялся.

## Формула

```
entry_runtime = base_alloc(obj#1) + LE.eip = align16(P) + 0x10 + 0xFC704
```
где P — база XMS-блока DOS/32A. В DOSBox-X (memsize=64): **0x20D714**
(подтверждено брейкпоинтом). Диапазон: [0x20D714, ~0x40FD704) при memsize=64.

ESP = base(obj#3) + 0x6F170 — не фиксирован заранее.

## Рантайм-контроль

- `DOS XMS` — база P пула;
- `DV T*16+0x32C0` — `_app_eip` (точный вход);
- `DV T*16+0x30E0` — `_sel32_cs`;
- `SELINFO CS` — плоский 32-битный селектор приложения;
- `GDT` — таблица дескрипторов (пейджируется, выход `Q`).

## Прочие находки

- `core=debug` невалиден в конфиге → сброс на `auto` → после CR0.PE ядро уходит
  в dynamic; для отладки нужен **`core=normal`**.
- `SR` — команда ЗАПИСИ регистров; чтение — из дампа экрана (окно Register Overview).
- `BPINT` в этой сборке работал ненадёжно (сеанс A не останавливался на FF87-зонде);
  цепочка из обычных `BP` — рабочий путь.
- Вывод `GDT`/`HELP` пейджируется: следующий `RUN` после пейджера уходит в него
  как ENTER — нужен `Q` перед продолжением.

## Сеансы

- **A** (захват T): `BPINT 21 FF` / `RUN` / `WAIT 30` → стоп на FF87-зонде
  (CS=T+0x2DD) → T=CS−0x2DD. В практике T получили из первого стопа цепочки BP.
- **B/В** (цепочка): см. `cmds_c.txt` — BP на MZ-entry, свитч RM→PM, @@swpm,
  enter_32bit_code и кандидаты входа; после каждого останова — `GDT`, `Q`, `RUN`.
