# Анимация спрайтов юнитов в оригинальной DOS-игре (MAXRUN.EXE)

Статус: **подтверждено эмпирически** (покадровая AVI-съёмка в DOSBox-X,
70.007 fps, ~118 с игрового времени / ~8300 кадров; см. §7 «Результаты
съёмки»). Открытый вопрос: кадры дрели шахты 1..15 в idle-состоянии не
проигрываются — см. §7.4 «Гипотеза». Дата сессий: 2026-11-18.

---

## 1. TL;DR

| Вопрос | Ответ |
|---|---|
| Где кадры анимации | В `MAX.RES` как мультикадровые спрайты (ImageMultiHeader), формат в `formats/spw.md` |
| Шахта (MININGST) | **24 кадра**: 16 полных (116×108, hot=(58,55)) + 8 частиц (10×40…25×13) — буровой мусор |
| Электростанция (POWGEN) | **6 кадров**: 2 корпуса 63×60 + 4 дымовых клуба (14×10/10×16/17×10/10×16) |
| Конструктор (CONSTRCT) | **40 кадров** 26×61 (лента в `max-brh-assets/images/sprites/units/CONSTRCT_26x61_40f.png`) |
| Логика анимации (оригинал, эмпирически) | **В покое корпус зданий НЕ листается** (шахта всегда кадр 0, POWGEN — кадр 0/1 статичен). Мигание маяков/дым — **палитровые цветовые циклы** (WRL color cycling), а не кадры спрайта. Листание кадров корпуса — только при активной работе (гипотеза, §7.4) |
| Частота | Маяки шахты: фаза 166.7 мс (1/6 с), цикл 666.7 мс. Дым POWGEN: смена ~214 мс. См. §7.3 |
| Палитра отрисовки | Мировая (WRL): слоты 64–159 из палитры мира, командные 32–39/48–55 через LUT команды |

## 3. Логика анимации (порт + сверка с оригиналом)

- `UnitsManager_ProcessOrderSentry` (units_manager.cpp:2902): для юнита с
  флагом `ANIMATED` и включёнными эффектами (`effects=1`): `image_index+1`,
  при превышении `image_index_max` — заворот на `image_base`; иначе —
  `UnitInfo::Animate()` (покачивание/дрожание, БЕЗ листания кадров).
  Вызывается из `UnitsManager_ProcessOrders()`.
- `GameManager_ProcessTick` (game_manager.cpp:5273): `ProcessOrders()`
  выполняется **только когда есть CPU-бюджет**
  (`TickTimer_HaveTimeToThink(TIMER_FPS_TO_MS(24))`). При медленной эмуляции
  (DOSBox cycles=fixed 200000) листание кадров может вообще не выполняться.
- **Палитровые циклы** — отдельный механизм: `World::UpdateColorAnimations`
  (world.cpp:190) + `InitColorCycles` (world.cpp:542), вращение DAC-слотов:
  диапазоны 9–12 @9 fps, 13–16 @6 fps, 17–20 @9 fps, 21–24 @6 fps,
  25–30 @2 fps, 31 @6 fps, 96–102 @8 fps, 103–109 @8 fps, 110–116 @10 fps,
  117–122 @6 fps, 123–127 @6 fps. Именно они дают мигание маяков зданий и
  дым (эмпирически подтверждено, §7.3).
- Выключение анимации: настройка `effects=0` (MAX.INI [PREFERENCES]).
- Частицы (кадры 16..23 шахты) — рисуются по hot-смещениям относительно
  якоря здания; **в оригинале рисуются все 8 одновременно и статично**
  (§7.2), а не циклически.

## 4. Эмпирическая съёмка в DOSBox (что сделано и что работает)

### 4.1 Окружение

- Docker-образ `max-dosbox-anim` (Dockerfile: `build/anim-dos/Dockerfile.anim`):
  Xvfb + openbox + xdotool + ffmpeg + сборочные зависимости.
- DOSBox-X 2022.09.1 (исходники `max-original-dasm/tools/dosbox-x/`),
  собран с `--enable-debug=heavy --enable-sdl2`. Для M.A.X. бинарь
  **пропатчен** (см. 4.3) — резервная копия исходного: `build/anim-dos/dosbox-x.orig`.
- Конфиг: `build/anim-dos/maxrun-sb16.conf` (обязательно `sbtype=sb16` на
  IRQ7/DMA5/220h, `autolock=false`, `show recorded filename=false`,
  `captures=/src/build/anim-dos/captures`).
- Запуск: `python build/anim-dos/driver.py start` (pty-раннер
  `build/anim-dos/pty_run.py` + FIFO `build/anim-dos/cmd.fifo` для команд дебаггера).

### 4.2 Обязательные условия запуска игры (выяснено эмпирически)

1. **Sound Blaster**: без эмуляции SB16 игра выходит в DOS после стартового
   текстового экрана (MAX.INI ждёт SB16 AWE32 на 220/IRQ7/DMA5).
2. **Путь данных**: игра запускается как `MAXRUN.BAT` → `MAXRUN.EXE -fD:\MAX`
   (монтировать каталог игры как `D:\MAX`). Скретч-копия игры:
   `build/anim-dos/game/MAX/` (оригинал `max-original/` не трогается).
3. **`show recorded filename=false`**: иначе после каждого скриншота
   всплывает xmessage «Recording completed», навсегда ворующий фокус окна.
4. Загрузка игры ≈ 2–4 минуты (cycles=fixed 200000, dynamic core).

### 4.3 Патчи DOSBox-X (нужны для M.A.X., иначе мышь мертва)

Все изменения в `max-original-dasm/tools/dosbox-x/src`:

1. `ints/mouse.cpp`, `Mouse_CursorMoved`: абсолютное позиционирование в
   графическом режиме работает и в защищённом режиме (было заблокировано
   `AllowINT33RMAccess()` — DOS/32A работает целиком в PM).
2. `ints/mouse.cpp`, `Mouse_Read_Motion_Data`: счётчики AX=0Bh отдаются и
   без захвата мыши; значения выводятся из АБСОЛЮТНОЙ позиции хоста
   (`mouse.x - last_abs_x`) — курсор гостя всегда следует за хостом.
3. `ints/mouse.cpp`, `INT74_Handler`: доставка событий мыши в обработчик
   пользователя (UIR) разрешена и в PM (было за `AllowINT33RMAccess()`).
4. Диагностические LOG_MSG в `Mouse_CursorMoved`/`HandleMouseMotion`/
   `HandleMouseButton`/`INT33_Handler` — можно оставить или вычистить.

Без этих патчей: курсор гостя застывает в (320,240), клики не доходят до
игры (игра интегрирует микки из AX=0Bh и не синхронизируется по AX=3).

### 4.4 Управление сессией

- Скриншоты: F12+P (хост-ключ F12) → `captures/maxrun_NNN.png` (нативный
  640×480, не зависит от масштаба окна).
- Клавиши: `build/anim-dos/key.sh <xdotool-keys>`.
- Клики: `build/anim-dos/click_abs.py X Y` (с калибровкой смещения курсора).
- Дебаггер: Alt+Pause; команды через FIFO (внимание: при нераспознанной
  команде строка ввода не очищается — сначала валидная команда или перезапуск).
- Состояние экрана: `match_native.py` (сравнение с декодированными экранами
  `max-brh-assets/images/ui/*_ownpal.png`).

### 4.5 Пройденный путь (навигация, проверено по скриншотам)

```
MAINPIC (0.68) → click «New Game» (440,195) → PLANETSE (0.51) →
Shift+Return (Done) → OPTNFRM (0.96) → Return (Done) → выбор игрока →
новая игра, база приземлилась (FRAMEPIC, зум 64).
Load Game: MAINPIC → Shift+L → LOADPIC (0.97) → клик слота 10 (save10.dta
«Turn 2») → игра загружается (проверено: экран меняется на игровой).
```

## 5. Сейв-файлы (разбор)

- `max-original/save10.dta` = кастомный сейв «Turn 2», формат V70 (байт 0 = 0x46).
  Формат = сырые little-endian структуры (порт реверснул его как SmartFile V70).
- Записи юнитов: `u16 unit_type; u16 id; u32 flags; i16 x; i16 y; i16 grid_x;
  i16 grid_y; u16 name_len; name; ...`. Скан (`build/anim-dos/scan_save2.py`)
  находит в save10.dta ДВЕ базы: шахты MININGST на grid (22,22) и (74,77)
  (рядом DOCK/SHIELDGN), flags=0x01604210.
- Мир сейва определяется SHA-256 WRL-файла по таблице
  `SaveLoad_TranslateWorldIndexToHashKey` (порт, saveload.cpp:1569):
  индекс 0 = `SNOW_1.WRL` (карта 112×112).
- В новой игре шахта деплоится по `GameManager_GetStartPositionMiningStation`:
  стартовая позиция (если ресурсов хватает) либо спиральный поиск в радиусе
  до 9 клеток; POWGEN — не далее 2 клеток от шахты
  (game_manager.cpp:1794–1852).

## 6. Блокеры (что не удалось / ограничения)

1. **Листание кадров дрели шахты (1..15) не поймано.** В idle-состоянии
   (после посадки, до/после попыток End Turn) корпус всегда кадр 0 — за
   ~118 с игрового времени (5 AVI-захватов, ~8300 кадров) ни одного перехода.
   Гипотеза — кадры дрели проигрываются только при активной добыче
   (обработка хода) либо требуют CPU-бюджета `ProcessOrders` (§3).
2. **Мышь в меню загрузки нестабильна.** Клик по слоту в LOADPIC вводит
   режим текстового редактирования имени сейва: курсор игры замирает на
   позиции клика (модальный ввод), клики по кнопке LOAD не проходят;
   Escape выходит из режима редактирования (курсор возвращается), но клики
   в меню всё равно ненадёжны. Загрузка save10.dta в этой сессии не
   доведена до конца.
3. **Матчинг POWGEN занижен** (NCC ≈ 0.80–0.82 против 0.876 у шахты):
   дым/огни POWGEN — палитровые циклы, цвета части пикселей отличаются от
   эталона. Позиция определяется, но слабее.
4. **Дебаггер DOSBox-X**: строка ввода не очищается после нераспознанной
   команды (ESC блокируется в getch) — для чтения VGA DAC пришлось бы
   писать валидные команды строго по одной (не использовался).

## 7. Результаты покадровой съёмки (сессия 2026-11-18, AVI @70.007 fps)

> **Уточнение (2026-11-19, при переносе в Rust-порт — §9):** «8 частиц» шахты из
> §7.1 — это **кадры-коннекторы** `D_MINING.connector_image_base = 16` (рисуются
> по маске `connectors`, в плотной базе выставлены все 8); «4 дымовых клуба»
> `POWGEN` из §7.3 — тоже коннекторы (`D_SMLBLD`, 4 трубы N/E/S/W), а кадры
> «дыма» в `proof/powgen_smoke.png` — **рамка выделения инженера**. Анимации
> дыма в данных игры нет; корпус `POWGEN` статичен.

Методика: видео-захват DOSBox-X (F12+I, AVI+ZMBV,
`skip encoding unchanged frames=false` по умолчанию — в AVI попадает
**каждый отрисованный кадр**), извлечение кадров ffmpeg, masked NCC
(FFT-корреляция) эталонов `mine_ref_game.npz` / `powgen_ref_game.npz`.
Серия: новая игра (MAINPIC → New Game (440,195) → Shift+Return → Return →
посадка), без скроллов; захваты maxrun_000..004.avi
(3.57 + 52.34 + 11.38 + 26.65 + 24.25 с игрового времени).

### 7.1 Шахта найдена и отмачена

- Корпус: top-left **(218, 377)**, якорь **(276, 432)** (кадр 0,
  116×108, NCC 0.876) — камера после посадки показывает базу; шахта в
  правой части кадра (без скроллов и кликов по миникарте).
- Все **8 частиц** (кадры 16..23) отрисованы **одновременно** по
  hot-смещениям от якоря (NCC 0.70–0.89), статичны на протяжении всех
  захватов.
- Доказательство: `build/anim-dos/proof/mine_found.png` (кроп с рамкой и
  якорем), `full_view.png` (полный кадр с разметкой).

### 7.2 Корпус шахты в idle НЕ анимируется

Во всех ~8300 кадрах (суммарно ~118 с) лучший матч корпуса — **кадр 0**,
NCC 0.8758–0.8762, ни одного перехода 0→1→…→15. Частицы тоже статичны
(mean NCC == max NCC по кадрам). Вывод: «цикл 0..15 в покое» из §2/§3
**не подтверждается**; кадры 1..15 (положения дрели) в покое не
проигрываются.

### 7.3 Мигание маяков и дым — палитровые циклы (не кадры спрайта)

- **Маяки шахты** (4 блока на мачтах: rel (33–35, 4–6)/(33–35, 95–97)/
  (76–79, 3–6)/(76–79, 94–97)): цикл цветов
  **жёлтый (252,252,156) → оранжевый (240,168,100) → красный (232,48,48) →
  оранжевый → жёлтый**, каждая фаза ровно **11.67 кадров = 166.7 мс**,
  полный цикл 46.67 кадров = **666.7 мс**. Точно совпадает с шагом
  палитрового цикла 6 fps (TIMER_FPS_TO_MS(6) = 1000/6 ≈ 167 мс) из
  `InitColorCycles` — маяки используют слот из вращаемого диапазона
  (4 цвета в диапазоне, два оранжевых идентичны → 4-фазный «пинг-понг»).
- **Индикатор у дрели** (rel (46–48, 12)): тёмный (72,56,36) большую часть
  времени + **красная вспышка (232,48,48) на 11.67 кадров каждые
  46.67 кадров** (500 мс тёмный + 166.7 мс красный).
- **POWGEN**: корпус ≈ top-left (145, 366) (63×60, NCC 0.80–0.82 — занижен
  циклами); **4 дымовых клуба** вокруг (y 144–208, x 368–440) непрерывно
  анимируются — содержимое меняется каждые **~15 кадров = 214 мс**
  (дым «плывёт», все 4 позиции заняты постоянно).
- Доказательства: `proof/beacon_phases.png` (4 фазы маяков в ряд),
  `proof/drill_indicator.png` (тёмная/красная фазы индикатора),
  `proof/powgen_smoke.png` (дым через 15 кадров).

### 7.4 Гипотеза (требует досъёмки)

Кадры дрели шахты 1..15 проигрываются **только при активной добыче**
(«Mining stations produce raw materials every turn» — продукция в момент
обработки хода) и/или когда `ProcessOrders` получает CPU-бюджет (§3).
В новой игре шахта на стартовой позиции, вероятно, без ресурсов под собой —
дрель не работает. Проверка: загрузить save10.dta (шахты на (22,22) и
(74,77), Turn 2), отцентрировать камеру кликом по миникарте
((15+22, 356+22) = (37,378) или (89,433)) и снять AVI в момент обработки
хода/активной добычи.

## 9. Применено в Rust-порте (2026-11-19)

Съёмка перенесена в `max-brh` (оракул `max-cpp-port` не менялся):

* **Палитровые циклы** — `max_render::palette::{COLOR_CYCLES, ColorCycles,
  rotate_palette}`: 1:1 порт `World::InitColorCycles`/`UpdateColorAnimations`
  (11 диапазонов, 2/6/8/9/10 fps, направления, слот 31). Применяются в
  рендере снимком системной палитры (`FRAMEPIC` + `.WRL`) поверх кадра;
  `dt = 0` палитру не вращает (golden стабильны). Маяки шахты — слоты 13–16
