# Анимация спрайтов юнитов в оригинальной DOS-игре (MAXRUN.EXE)

Статус: **частично подтверждено эмпирически** (декодированные кадры и логика
порта проверены; покадровую съёмку анимации в DOSBox довести до конца не
удалось — см. §6 «Блокеры»). Дата сессии: 2026-11-18.

## 1. TL;DR

| Вопрос | Ответ |
|---|---|
| Где кадры анимации | В `MAX.RES` как мультикадровые спрайты (ImageMultiHeader), формат в `formats/spw.md` |
| Шахта (MININGST) | **24 кадра**: 16 полных (116×108, hot=(58,55)) + 8 частиц (10×40…25×13) — буровой мусор |
| Электростанция (POWGEN) | **6 кадров** 63×60 |

| Логика анимации (порт) | «1 кадр за тик обработки приказов» для юнитов с флагом ANIMATED, с заворотом на первый кадр |
| Частота | В порте тик ≈ 24–30 кадров/с → цикл шахты 16 кадров ≈ 0.5–0.7 с; **в оригинале не замерена** |
| Палитра отрисовки | Мировая (WRL): слоты 64–159 из палитры мира, командные 32–39/48–55 через LUT команды |

## 3. Логика анимации (из C++-порта, требует эмпирической сверки)

- `UnitsManager_ProcessOrderSentry` (units_manager.cpp:3029): для юнита с
  флагом `ANIMATED` и включёнными эффектами (`effects=1`): `image_index+1`,
  при превышении `image_index_max` — заворот на `image_base`.
- Вызывается при обработке приказов (каждый игровой тик). В порте тик
  ≈ 24–30 Гц (TIMER_FPS_TO_MS(30/1.1) ≈ 36.7 мс бюджет, рендер 24 Гц).
- Выключение анимации: настройка `effects=0` (MAX.INI [PREFERENCES]) либо
  юнит не имеет ANIMATED.
- Частицы (кадры 16..23 шахты) — рисуются по hot-смещениям относительно
  якоря здания; в оригинале, вероятно, проигрываются циклически вместе с
  корпусом (0..23 с заворотом) либо корпус 0..15 + частицы по расписанию —
  **требует покадровой съёмки**.

## 4. Эмпирическая съёмка в DOSBox (что сделано и что работает)

### 4.1 Окружение

- Docker-образ `max-dosbox-anim` (Dockerfile: `build/anim-dos/Dockerfile.anim`):
  Xvfb + openbox + xdotool + ffmpeg + сборочные зависимости.
- DOSBox-X 2022.09.1 (исходники `max-original-dasm/tools/dosbox-x/`),
  собран с `--enable-debug=heavy --enable-sdl2`. Для M.A.X. бинарь
  **пропатчен** (см. 4.3) — резервная копия исходного: `build/anim-dos/dosbox-x.orig`.
- Конфиг: `build/anim-dos/maxrun-sb16.conf` (обязательно `sbtype=sb16` на
  IRQ7/DMA5/220h, `autolock=false`, `show recorded filename=false`,
  `captures=/src/build/anim-dos/captures`).
- Запуск: `python build/anim-dos/driver.py start` (pty-раннер
  `build/anim-dos/pty_run.py` + FIFO `build/anim-dos/cmd.fifo` для команд дебаггера).

### 4.2 Обязательные условия запуска игры (выяснено эмпирически)

1. **Sound Blaster**: без эмуляции SB16 игра выходит в DOS после стартового
   текстового экрана (MAX.INI ждёт SB16 AWE32 на 220/IRQ7/DMA5).
2. **Путь данных**: игра запускается как `MAXRUN.BAT` → `MAXRUN.EXE -fD:\MAX`
   (монтировать каталог игры как `D:\MAX`). Скретч-копия игры:
   `build/anim-dos/game/MAX/` (оригинал `max-original/` не трогается).
3. **`show recorded filename=false`**: иначе после каждого скриншота
   всплывает xmessage «Recording completed», навсегда ворующий фокус окна.
4. Загрузка игры ≈ 2–4 минуты (cycles=fixed 200000, dynamic core).

### 4.3 Патчи DOSBox-X (нужны для M.A.X., иначе мышь мертва)

Все изменения в `max-original-dasm/tools/dosbox-x/src`:

1. `ints/mouse.cpp`, `Mouse_CursorMoved`: абсолютное позиционирование в
   графическом режиме работает и в защищённом режиме (было заблокировано
   `AllowINT33RMAccess()` — DOS/32A работает целиком в PM).
2. `ints/mouse.cpp`, `Mouse_Read_Motion_Data`: счётчики AX=0Bh отдаются и
   без захвата мыши; значения выводятся из АБСОЛЮТНОЙ позиции хоста
   (`mouse.x - last_abs_x`) — курсор гостя всегда следует за хостом.
3. `ints/mouse.cpp`, `INT74_Handler`: доставка событий мыши в обработчик
   пользователя (UIR) разрешена и в PM (было за `AllowINT33RMAccess()`).
4. Диагностические LOG_MSG в `Mouse_CursorMoved`/`HandleMouseMotion`/
   `HandleMouseButton`/`INT33_Handler` — можно оставить или вычистить.

Без этих патчей: курсор гостя застывает в (320,240), клики не доходят до
игры (игра интегрирует микки из AX=0Bh и не синхронизируется по AX=3).

### 4.4 Управление сессией

- Скриншоты: F12+P (хост-ключ F12) → `captures/maxrun_NNN.png` (нативный
  640×480, не зависит от масштаба окна).
- Клавиши: `build/anim-dos/key.sh <xdotool-keys>`.
- Клики: `build/anim-dos/click_abs.py X Y` (с калибровкой смещения курсора).
- Дебаггер: Alt+Pause; команды через FIFO (внимание: при нераспознанной
  команде строка ввода не очищается — сначала валидная команда или перезапуск).
- Состояние экрана: `match_native.py` (сравнение с декодированными экранами
  `max-assets/images/ui/*_ownpal.png`).

### 4.5 Пройденный путь (навигация, проверено по скриншотам)

```
MAINPIC (0.68) → click «New Game» (440,195) → PLANETSE (0.51) →
Shift+Return (Done) → OPTNFRM (0.96) → Return (Done) → выбор игрока →
новая игра, база приземлилась (FRAMEPIC, зум 64).
Load Game: MAINPIC → Shift+L → LOADPIC (0.97) → клик слота 10 (save10.dta
«Turn 2») → игра загружается (проверено: экран меняется на игровой).
```

## 5. Сейв-файлы (разбор)

- `max-original/save10.dta` = кастомный сейв «Turn 2», формат V70 (байт 0 = 0x46).
  Формат = сырые little-endian структуры (порт реверснул его как SmartFile V70).
- Записи юнитов: `u16 unit_type; u16 id; u32 flags; i16 x; i16 y; i16 grid_x;
  i16 grid_y; u16 name_len; name; ...`. Скан (`build/anim-dos/scan_save2.py`)
  находит в save10.dta ДВЕ базы: шахты MININGST на grid (22,22) и (74,77)
  (рядом DOCK/SHIELDGN), flags=0x01604210.
- Мир сейва определяется SHA-256 WRL-файла по таблице
  `SaveLoad_TranslateWorldIndexToHashKey` (порт, saveload.cpp:1569):
  индекс 0 = `SNOW_1.WRL` (карта 112×112).
- В новой игре шахта деплоится по `GameManager_GetStartPositionMiningStation`:
  стартовая позиция (если ресурсов хватает) либо спиральный поиск в радиусе
  до 9 клеток; POWGEN — не далее 2 клеток от шахты
  (game_manager.cpp:1794–1852).

## 6. Блокеры (что не удалось)

1. **Шахта не найдена визуально на экране.** Кадры 0..15 MININGST
   (с палитрой мира SNOW_1 и красным LUT — модель проверена: 93% пикселей
   экрана новой игры объясняются этой палитрой) не дают NCC > 0.88 ни в одной
   точке кадра. POWGEN аналогично. Причины-кандидаты:
   - камера не на базе (после скроллов позиция вида неизвестна, мышь
     «замерзала» на поздних этапах сессии — клики по миникарте перестали
     попадать);
   - команда игрока/перекраска LUT может отличаться от применённой
     (красная: 32–39,48–55 → 56–63);
   - возможна отрисовка через BRIGHTNESS-таблицы (затемнение).
2. **Ввод периодически «замерзает»** в игре (курсор гостя останавливается,
   стрелки перестают скроллить) — вероятно, состояние DEPLOYING/LANDING
   новой игры; нужен перезапуск сессии и немедленный замер после посадки.
3. **Дебаггер DOSBox-X**: строка ввода не очищается после нераспознанной
   команды (ESC блокируется в getch) — для чтения VGA DAC пришлось бы
   писать валидные команды строго по одной.

## 7. План досъёмки (следующая сессия)

1. Перезапустить контейнер, дождаться MAINPIC, New Game → Done → Done →
   посадка. СРАЗУ после посадки (без скроллов): сделать серию снимков
   (`burst.py 120 150 <prefix>` — F12+P каждые ~150 мс) и прогнать матчинг
   `mine_ref_game.npz` по всем кадрам серии; проверить POWGEN тем же способом.
2. Позиция шахты относительно базы: сетка кликов по миникарте вокруг
   центра (база ≈ центр карты) с шагом 5–8 px, после каждого клика — матчинг.
3. Частоту цикла считать по временным меткам серии: идентифицировать
   последовательность кадров и период (см. §2.1: ожидается цикл по
   кадрам 0..15 или 0..23).
4. Завод/конструктор: POWGEN — аналогично (цикл 6 кадров). CONSTRCT (40
   кадров) — поставить стройку в новой игре (Build menu → здание) и снять.
